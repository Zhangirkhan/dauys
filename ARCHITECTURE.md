# Архитектура

## Границы компонентов

- **shared** — единственный контракт. Action — discriminated union с конкретными parameters для каждого действия; неизвестные поля запрещены. Схемы реестра, envelope, результата и решения проверяются во время исполнения.
- **PWA** — UI и запись. Не имеет доступа к bootstrap-секрету или API-ключу. Fetch и WebSocket используют один origin; cookie HttpOnly. Service worker кэширует только оболочку.
- **server** — авторизация, SQLite, конвейер, контекст, политика риска, маршрутизация. Не выполняет команды macOS. Текстовый endpoint пропускает этап STT.
- **mac-agent** — отдельная identity, постоянное соединение, журнал исполнения и локальная конфигурация доверия. Работает за NAT через исходящий WebSocket.

## Конвейер и состояния

`transcribing → processing → confirmation/clarification/executing → done/error/cancelled`.

Загрузка ограничена 8 MiB; запись — 20 секунд. Upload сохраняется под сгенерированным именем в приватной temp-папке. STT удаляет свой WAV в finally; upload также удаляется после обработки. Отмена во время STT не запускает последующее действие, хотя текущий subprocess может завершить распознавание.

IntentResolver получает registry, availableActions, capabilities Shortcuts, последние 10 успешных команд, activeProject, lastApplication, lastFile, searchResults и pending. DeepSeek получает текстовые данные и схемы, JSON валидируется; после первого невалидного ответа предоставляется ошибка валидации и делается один повтор. Сетевые ошибки возвращаются без бесконечного retry.

После решения backend ещё раз проверяет action, ссылки на registry и политику подтверждения. Флаг модели не может снять обязательное подтверждение. Локальный агент повторяет проверку риска и идентификаторов.

## Поиск и уточнение

Search возвращает максимум 10 файлов. Один результат или запрос latest автоматически переходит к open_file. Несколько результатов сохраняются в CommandRecord и в контексте, PWA получает options. Ответ по ID, имени или порядковому номеру возобновляет тот же command ID. Новый текст/аудио при ожидаемом уточнении также считается ответом. Для языкового уточнения исходная фраза и варианты включаются в повторный IntentInput.

## Жизненный цикл и доставка

CommandRecord UUID относится к пользовательскому запросу. Для каждого шага на Mac создаётся **отдельный execution UUID**. Это позволяет выполнить search и затем open под одной пользовательской командой, не ослабляя защиту от повторов.

Envelope содержит createdAt/expiresAt исходного запроса; TTL <=60 секунд. Подтверждение не продлевает TTL. Агент проверяет срок, допустимый clock skew и записывает UUID в SQLite до системного вызова. Гарантия — **at-most-once попытка**, не exactly-once результат. Потеря связи после выполнения означает неопределённый результат; сервер не повторяет действие.

Ping/pong каждые 15 секунд, watchdog агента, reconnect с backoff 0.5–10 секунд. Замена соединения одной identity закрывает старое. Отзыв токена закрывает соответствующие сокеты. Сервер периодически истекает незавершённые команды; выключение дожидается фоновых задач и не обращается к БД после закрытия.

В MVP на пространство допускается одна незавершённая команда. Это сохраняет порядок контекста и исключает изменения реестра во время подтверждения. Контекст обновляется после успешного результата; неудачное действие не объявляется успешно выполненным.

## Хранение

`assistant.db`: devices (хеш токена), pairs (хеш кода и expiry), commands (JSON записи), contexts (JSON). SQLite WAL. `executions.db` на Mac — отдельный журнал ID, сохраняющий защиту при перезапуске. Старые ID удаляются лишь после того, как их TTL давно истёк.

`registry.json` заменяется атомарным rename после валидации. `agent-trust.json` доступен только локально. `.env` и token-файл имеют права 0600. Папка данных создаётся с 0700. История содержит пользовательский текст и пути; для шифрования диска используйте возможности ОС (например, FileVault).

## Выбранные совместимые технологии

Node 24 с node:sqlite; Fastify 5; ws; React 19; Vite 6; Tailwind 3; vite-plugin-pwa; Zod 3; Vitest 3. Версии зафиксированы lockfile. TypeScript backend/agent собираются tsup, UI — Vite. Pino не логирует тела аудио, токены или ключи.

MLX требует Apple Silicon. Docker собирает JS и UI, но не заменяет Mac для STT/Automation. Не реализованы push-уведомления, фоновые команды, несколько одновременно активных запросов, streaming STT или TTS: итог отображается текстом.

## Локальный интерпретатор

`LocalIntentResolver` — отдельный рабочий провайдер для открытия приложений/проектов без облака. Он требует явного действия или названия зарегистрированного объекта, предпочитает составное имя целиком, возвращает уточнение при неоднозначности и не подставляет старый активный проект вместо явно названной программы. Mock остаётся отдельным провайдером для тестов. STT и режим исполнения выбираются независимо.
